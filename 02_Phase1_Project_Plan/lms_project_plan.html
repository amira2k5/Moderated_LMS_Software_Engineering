Moderated Learning Management System

Project management plan (Phase 1). Waterfall, 7 weeks, one developer.

This plan covers the feasibility study, work breakdown structure, schedule and risk register. Figures marked assumed are my planning assumptions: replace them with your own before you submit.

1. Feasibility study

DimensionAssessmentVerdict
TechnicalC++17, SQLite, CMake, GoogleTest and libsodium are mature, free and run offline on old hardware. 800 students means a few tens of thousands of rows, which SQLite handles easily. The main risk is developer experience with C++ and the build tooling, not the technology.Feasible
OperationalTeachers are not IT experts, so the interface must be simple. A menu-driven console application with role-specific menus meets the need and runs on old machines. A desktop GUI is deferred (Won't have in v1.0). Training is covered by one manual per role.Feasible, with simple UI
EconomicNo licence cost: SQLite is public domain, libsodium is ISC, GoogleTest is BSD-3. It runs on the existing school computer. Effort is about 245 hours (assumed 35 h/week for 7 weeks). Ongoing cost is low: backups and occasional updates.Feasible
LegalThe system holds learners' personal data and assessment records, so data protection law applies (confirm which law governs your school). Mitigations: store only the data needed, enforce role-based access, hash passwords, keep an audit log of mark changes. Dependency licences permit use in a school.Feasible, with controls
ScheduleThe 7-week deadline is fixed and the phases overlap in weeks 2, 4 and 5. Gate 1 (end of week 2) and Gate 2 (end of week 3) leave little slack. The critical path has about 0.1 weeks of buffer at each gate.Tight
Recommendation: proceed. The project is technically and economically sound and the main exposure is time. Proceed on three conditions: (1) a console UI in v1.0, (2) scope held to the MoSCoW Must and Should items, (3) risk register reviewed at every gate. Out-of-scope items from the case study stay out.

3. Schedule

The Gantt chart shows tasks against weeks 1 to 7. Arrows are finish-to-start dependencies. Diamonds are milestones (phase gates and the v1.0 release). Red items are on the critical path.

Critical pathTask with slack◆ Milestone

Critical path

Stakeholder analysis, SRS, use case model, Gate 1, architecture, class diagram and design document, Gate 2, repository and CI setup, domain model, unit and integration tests, system and acceptance tests, Gate 3 and v1.0, CR1 analysis, CR1 implementation, regression tests, final report. Any slip here moves the final date. The data-access layer, services and UI, test plan, static analysis and documentation all have slack of 0.1 to 0.7 weeks.

Milestones: Gate 1 end of week 2 (SRS and use cases baselined), Gate 2 end of week 3 (design approved, implementation may start), Gate 3 end of week 6 (tests passed, v1.0 tagged), v1.1 end of week 7.
